## 5. Deployment Notes

- **Execution order** - deploy changeSets strictly in the generated order (ids are sequential; source order is preserved and checked for dependency problems - see ORDER_DEPENDENCY findings).
- **Dry run first (no DB changes):** `liquibase --changelog-file=db.changelog-1.0.xml validate` then `liquibase update-sql > update_preview.sql` and review the exact SQL.
- **Tag before deploy:** `liquibase tag --tag=PROJECT_1.0_pre` (the XML changelog also contains a tagDatabase changeSet) so `liquibase rollback --tag=PROJECT_1.0_pre` is possible.
- **Preview rollback:** `liquibase rollback-sql --tag=PROJECT_1.0_pre` must produce SQL with no TODO/MANUAL markers.
- **House formatted-SQL package:** run deploy scripts in file-number order, then confirm all tracker rows in `` are COMPLETED. Rollback package: run the `*_ROLLBACK.sql` script (forward execution) or `liquibase rollback` (inline --rollback).
- **Locking:** set `SET lock_timeout = '5s'` and `statement_timeout` for the deployment session; retry on lock timeout rather than queueing behind long transactions.
- **Data loss protection:** confirm a fresh backup (RMAN / expdp / pg_dump / mysqldump) and that the generated `-bkp` backup changeSets ran before the destructive change. Keep backup tables until the release is signed off, then drop them in a later release.
- **Application compatibility (expand/contract):** release application code that no longer reads/writes dropped columns BEFORE this database change.
- **Dependent objects:** verify views/routines still compile/execute after the change.
- **Optimizer statistics:** refresh stats on altered/indexed existing tables: `ANALYZE <schema>.<table>;`
- **Grants/roles:** confirm target roles exist in every environment (pre-check) - missing roles fail the GRANT and halt the deployment.
- **Data migration:** DML is in separate changeSets. Compare the pre/post row counts; for >100k rows rewrite as batched PL/SQL / chunked updates to limit undo and lock time.
- **Replaced objects:** capture current source with the DBMS_METADATA pre-checks and re-run the agent with `--baseline` so rollback restores the previous version instead of dropping the object.
- **Offline guarantee:** the agent and Liquibase run locally; Liquibase resolves the dbchangelog XSD from its own jar, so no network access is required.
